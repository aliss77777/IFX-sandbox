# Story 1.4: Streaming "Hello World"

## Status
Ready for Review

## Story
**As a** developer,
**I want** to implement a "hello world" that streams a sample image and text over a WebSocket,
**so that** I can prove the core real-time architecture is working end-to-end.

## Acceptance Criteria
1. The `ifx-app` establishes a persistent WebSocket connection to the `/ws` endpoint.
2. When the user sends a message, the backend immediately sends a WebSocket message containing a hardcoded image URL (e.g., `{"type": "asset", ...}`).
3. The `ifx-app` displays the image.
4. The backend then sends a stream of hardcoded `text_chunk` messages.
5. The `ifx-app` renders these chunks as a "typing" text effect.
6. The backend sends a final `stream_end` message.

## Tasks / Subtasks
- [x] Task 1: Modify the `/ws` endpoint in `app/main.py` to send a hardcoded asset and text stream. (AC: 2, 4, 6)
- [x] Task 2: Implement the WebSocket connection and message handling in the `ifx-app`. (AC: 1, 3, 5)
- [x] Task 3: Add a test for the streaming "Hello World" functionality.

### Backend Architecture
- The backend is a FastAPI application. The main entry point is `app/main.py`. [Source: docs/architecture/5-backend-architecture.md]
- The WebSocket endpoint is at `/ws`. [Source: docs/architecture/5-backend-architecture.md]

### Frontend Architecture
- The frontend is a Vite + React (TypeScript) application located in the `ifx-app` directory. [Source: docs/architecture/4-frontend-architecture.md]

### Communication Protocol
- Communication between the frontend and backend will be exclusively over WebSockets. [Source: docs/architecture/7-communication-protocol.md]
- The server will send the following messages:
  - `asset`: A JSON message containing the URL or data of the visual asset.
  - `text_chunk`: A JSON message containing a chunk of the streamed text response.
  - `stream_end`: A JSON message indicating the end of the text stream.
